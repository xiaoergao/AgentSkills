# HPM5301 调试器：经验、失败过程和验收边界

## 总适用范围

仅 [技能入口](../SKILL.md) 所列 HPM6E8Y 板、HPM5301IEG1、HSLink-Lite 2.4.7 本板 r2、SDK 1.13.0。时间为 2026-10-05；以下是当时记录及补丁的整理，本次没有重新擦写、复位或实板复测。各经验的管脚/地址不能直接用于其他板或固件格式。

## D01：USB2 不枚举，先核对 ROM 能力和固件状态

- **适用/证据**：本板 U6 的首次启动，生产资料、芯片资料和 UART ISP 成功记录。
- **踩坑**：按住 SW5 插 USB2、供电灯亮，却看不到 USB 设备；继续换 USB 驱动不能替代芯片启动方式确认。
- **正确动作**：本板 HPM5301IEG1 首次使用 UART0 ROM ISP；不要等待它像主控 USB1 一样枚举 USB ROM 下载器。HSLink 固件烧好并正常运行后 USB2 才提供 CMSIS-DAP/CDC。
- **边界**：不表示所有 HPM 芯片/封装都没有 USB ROM ISP；电源灯亮也不能证明全部电源、时钟、复位或 USB 线路正常。

## D02：HSLink 和 CherryDAP 要分清仓库、项目及板型

- **适用/证据**：本案 CherryDAP 固定上游提交、源码补丁及构建记录。
- **踩坑**：将“下载 HSLink 还是 CherryDAP”视为完全独立选项，或直接采用名称相似的 EVK 预编译固件。
- **正确动作**：选择 CherryDAP 仓库中的 HSLink-Lite，使用本板 `hslinklite / flash_xip / Release` 适配。不要启用 `CONFIG_HPM5301EVKLITE`；其引脚与本板不匹配。
- **边界**：该选择不是对所有 HSLink-Pro、其他板型或更新版本的推荐；升级需重新对比子模块、BSP 和生命周期实现。

## D03：TTL 与多路供电可能阻止完整复位

- **适用/证据**：本板 USB2 供电、TTL 信号仍连接以及 USB1/其他电源可能存在的恢复操作；多电源方法可迁移，具体序列需按板核对。
- **接线**：3.3 V TTL；PAD1/ISP_TX/U6 PA00 → TTL RXD，PAD2/ISP_RX/U6 PA01 → TTL TXD，PAD3 → GND；不接 TTL 的 VCC/5 V。
- **正确动作**：拔掉 USB2、TTL USB、USB1 和其他供电，等灯灭再等 5 秒；按住 SW5 插 USB2，松开后最后插 TTL USB。检查信号线固定、共地和逻辑电平。
- **边界**：只拔 USB2 可能仍经信号脚反向供电；等待秒数不是通用放电保证。无仪表时资料只能核对设计/贴装可能性，不能证明实际焊接和电气状态无误。

## D04：串口失败先恢复可靠链路，不盲改波特率

- **适用/证据**：本次不可靠杜邦线造成的通信中断、重试记录；本案 ROM V1.2.0。
- **踩坑**：备份/传输中断后反复续传；尝试只把 PC 波特率调低，但 ROM 尚未协商变速。
- **正确动作**：线接稳、完整断电重新进 ISP，默认 115200 建链；本案采用小分包/帧间间隔。需要变速时先通过 ROM `configure-rte`，不能只改主机波特率。写入途中超时表示固件可能不完整，必须重新验证。
- **边界**：115200 是此版本已验证配置，不是所有 MCU 的默认值；本案没有证明所有串口失败都由接触不良导致。

## D05：BIN 不一定从 Flash 基址写起

- **适用/证据**：本板 r2 的 `HSLink-Lite.bin`，141256 字节，`flash_xip` 镜像布局与读回记录。
- **踩坑**：把 `0x80000000` 的 Flash 映射基址当作任何 BIN 的起始地址，或者假定已装 UF2 bootloader。
- **正确动作**：此 BIN 写 U6 的 **`0x80000400`**，包含相应 NOR 配置与启动布局；不是从 `0x80000000` 开始的原始 Flash dump。本版不装 UF2 bootloader、不改 OTP，不能承诺拖拽 UF2 更新。
- **边界**：地址依赖镜像格式/链接脚本/启动器；不要推广到 ELF、整片备份、其他 bootloader 或主控 U3 应用。

## D06：每块板自己的备份，完整读回才是烧录证据

- **适用/证据**：本次单板恢复包和 ROM V1.2.0 的工具能力。
- **本次记录**：首次备份从 `0x80000000` 起 143360 字节，全部 FF；并非整片 Flash 备份。恢复脚本使用该历史备份，不是每次自动获取新备份。
- **正确动作**：新板先单独读取待修改区域/必要配置并保存范围、板身份和哈希；选择范围要覆盖实际擦除单元及需保留区域。此 ROM 不支持工具的 `verify-checksum`，以整个写入镜像完整读回逐字节比较，再执行冷复位。
- **边界**：另一块板可能已有启动器/配置，不能复用本板全 FF 文件。读取成功不等于备份覆盖所有有价值数据；命令返回成功也不等于运行正确。

## D07：第一次连接成功，不代表 USB 重开状态正确

- **适用/证据**：本案固定上游版本的 `dap_main.c` 请求/响应环形队列和 r2 补丁；软件重复连接测试。
- **踩坑**：主机重开 WinUSB 可能再次 CONFIGURED；首个 OUT 传输固定写槽 0，但旧请求/响应索引、计数和 idle 状态未同步清零，导致第二次连接应答错位。
- **修复**：本案在 RESET/CONFIGURED 统一重置请求/响应输入输出索引和计数、idle、`DAP_TransferAbort`，然后重新挂接首个接收。连续 5 次 OpenOCD JTAG 连接通过。
- **边界**：不能给所有 USB 栈机械添加同一回调。必须先确认旧异步传输已失效、执行上下文/并发和所有权；软件重开通过不代替物理断电、拔插和长时间验证。

## D08：复位位图与真实 GPIO 输出都要核对

- **适用/证据**：本板上游适配差异，`main.c`、`DAP_config.h`、`pinmux.c` 补丁。
- **修复**：复位模式字段应为 `(1U << RESET_NRST)`，不能直接塞枚举索引；启用 PB15 的 nRESET 输出。关闭本板不存在的可调供电级初始化，USB 设备模式不初始化不存在的 ID/OC/PWR 信号。
- **本板 JTAG**：PB11 TCK、PA29 TMS、PB13 TDI、PB12 TDO、PB14 TRST、PB15 SRST；目标串口桥 UART2 PA08 TX/PA09 RX。
- **边界**：不要以“通用 SDK 初始化”名义驱动未知电源/复位脚；目标电源控制、复位极性和 pinmux 随板改变。已启用代码路径不等于每项电气时序都完成仪器验收。

## D09：调试接口、串口、目标 ELF 和 Flash 算法分开验证

- **适用/证据**：Windows 下本板 CMSIS-DAP v2、JTAG 1 MHz 与 OpenOCD 的成功记录。
- **正确动作**：USB Bulk CMSIS-DAP v2 用于 JTAG，不使用 CDC COM 口；不要按本次 COM 编号硬编码，端口号可能变化。调主控时加载主控自己的 ELF，不能加载 U6 的 HSLink-Lite.elf。日常 USB2 调试松开 SW5，无需接 TTL 或重刷调试器。
- **验收**：分别确认 USB 枚举、目标 ID、重复连接、halt/PC/step/resume、加载与读回；结束前恢复目标运行。
- **边界**：看到 CDC 不代表桥接串口收发已测；看到 JTAG ID 不代表主控外部 Flash 已支持。后续主控 RAM 程序加载成功也不证明掉电保留。

## 过程与结果摘要

| 阶段 | 实际处理 | 结果与边界 |
| --- | --- | --- |
| USB2 无设备 | 检查原理/生产资料并核对 U6 型号和启动方式 | 改用 UART0 首次 ISP，不凭无枚举判板坏 |
| 备份通信中断 | 完整断电重进 ISP、检查接触、保留失败记录 | 未将中断报告为完成；后续用户确认 TTL 原先不可靠 |
| 速率尝试 | 识别 ROM 默认速率和变速握手限制 | 最终使用已验证 115200、小分包及间隔 |
| 固件适配 | 本板 pinmux/供电/NRST、XIP 构建与 USB 重连队列修复 | r2 单独发布，未安装 UF2 或改 OTP |
| 最终烧录 | 141256 字节写入并完整读回 | 逐字节相同，ROM 冷复位通过 |
| 调试验证 | CMSIS-DAP/CDC 枚举，JTAG 1 MHz 重连 5 次 | 主控 ID `0x1000563D`；暂停、PC、单步、恢复通过 |
| 后续网络开发 | USB2 加载主控 RAM 测试程序 | RAM 下载通路得到后续使用，外部 Flash 算法仍未验收 |

冻结调试器记录没有完成的独立验收：烧录后物理全断电启动专项、目标串口桥收发、长期稳定、高速 JTAG、主控外部 Flash 下载。后续正常使用不能替代缺失的专项测试报告。
