# 网络联调经验：每条经验的适用范围

本文属于 [bringup-hpm6e-network](../SKILL.md)，全部实测证据来自 2026-10-05 单块 HPM6E8Y 板和 SDK 1.13.0。每节的范围进一步收窄总范围；“方法可迁移”不等于实现可以直接复制。历史证据位置见 [过程记录](case-study.md)。

## N01：先证明板级映射

- **适用**：自制板或与 EVK 引脚不同的 SDK 移植；证据为本板网表、芯片封装表、SDK 复用定义及 PHY 实读。
- **本次坑**：早期引用 PE20–PE31 的可选复用，实际 ETH0 是 TSW 端口 3（索引 2），RGMII 为 PF02–PF13，PF00 MDC、PF01 MDIO、PF15 低有效复位。PHY 地址 0，ID `0x001CC916`。
- **做法/验收**：交叉核对网表网络名、封装球位、GPIO/复用和实例编号，先读 PHY ID，再验证真实收发。
- **不能外推**：这些引脚和地址只属于本板；PF14 PHY 中断没有使用，不代表未使用 TSW DMA 中断。

## N02：中断是通知，完成队列才是工作量

- **适用**：HPM6E00 TSW S2MM 命令/响应 FIFO 接收；证据为手册 68.3.10、源码和故障快照。
- **本次坑**：原代码每 1 ms 轮询 SDK IRQ 标志、每轮最多 8 帧。停滞时 MAC 收帧增长、CPU 出口溢出增长，但完成 FIFO 为空，仍有 7 项命令。不能据此说“完成中断丢了”或“描述符全用完”。
- **做法/验收**：短 ISR 屏蔽源并通知任务，任务按响应 FIFO 非空状态批量取包、归还描述符后恢复中断，保留有界超时唤醒。核对中断优先级是否满足当前 FreeRTOS port 的 ISR API 约束。看各层计数是否持续推进，不把通知次数当帧数。
- **不能外推**：本控制器深度 16 的硬件队列不是字节 ringbuffer，也不是所有网卡通用的链式描述符 ring；本案没有定位精确触发帧或证明芯片勘误。

## N03：DMA 内存、帧边界、所有权要一起管理

- **适用**：本案非缓存 DMA 接收/发送与复制到 lwIP pbuf 的实现；方法可迁移到有 DMA 的系统。
- **做法/验收**：本案使用 16 × 1600 字节、32 字节对齐的非缓存 RX 缓冲；逐个核对描述符 ID、长度、LAST，缓冲只归还一次。不支持跨描述符重组时丢弃到帧尾，避免把尾段当新帧。TX 短帧补零到 60 字节（不含 FCS），DMA 未完成或超时不能立即复用在途缓冲。
- **不能外推**：缓存维护/对齐/屏障由具体 MCU 和内存区决定；1600 不是“支持任意大包”的声明。需要 jumbo、多段或零拷贝时要重做所有权和重组设计。

## N04：检查整个接收链的容量与调度

- **适用**：本案 FreeRTOS + lwIP `NO_SYS=0`、非 core-locking-input、USB/ETH 共享 tcpip 线程；实测对照支持。
- **本次坑**：DMA 增至 16 后，默认 `MEMP_NUM_TCPIP_MSG_INPKT=8` 仍限制入队；扩池之后又出现 pbuf 耗尽，说明只扩大 ring 或邮箱不够。
- **做法/验收**：逐层检查 DMA → pbuf → 入站消息池 → mailbox → 消费者运行机会 → 缓冲释放。本案最终 pbuf 24 × 1600、入站消息 24、mailbox 32，tcpip 优先级 4 高于 ETH 接收任务 3，USB 收发任务为 4。双接口并行并检查所有资源失败计数。
- **不能外推**：不是所有项目都该采用 16/24/32 或优先级 4；考虑总内存、其他消息、任务执行时间和调度规则。未来运动任务的实时预算未验证。

## N05：业务过滤必须声明协议边界

- **适用**：本案只读 IPv4 管理接口，不提供 IPv6、mDNS、IGMP、VLAN 服务。
- **做法/验收**：仅将本机/广播目的 MAC 的 IPv4/ARP 交给共享协议栈。主动过滤单独记 `rx_filtered`，不能合并进溢出后宣称“无丢包”。同时观察 queue-full、内存失败、硬件溢出和帧错误。
- **不能外推**：这会丢弃上述未实现协议。尤其不能复制到 EtherCAT 原始帧端口（其 EtherType 为 `0x88A4`）；增加发现服务、VLAN 或其他协议时必须修改过滤及测试。

## N06：协商能力、实际速率和 MAC 配置必须一致

- **适用**：本板 RTL8211F + HPM6E00 TSW RGMII 路径；只在核对匹配 PHY/手册后使用寄存器示例。
- **本次实现**：PHY reg9=`0x0200` 宣告 1000FD，reg4=`0x0101` 宣告 100FD，reg0=`0x1200` 使能/重启协商；MAC 根据实际结果切换 GMII/MII 和速度字段。本路径不宣告 10M/半双工。
- **板级条件**：PHY page `0xD08` reg `0x11` bit8 和 reg `0x15` bit3 开启 TX/RX 延迟，MAC 延迟为 0；本实现未启用 EEE。延迟预算需要结合布线和双方接口设计，不能两端重复添加。
- **验收/边界**：最终单板实读 1000 Mbps，双接口功能回归通过；新版本在仅百兆对端上的协商和物理速率切换未测试。千兆链路不等于应用能跑 1 Gbit/s。

## N07：PC 抓包是局部观察，不能替代交换机配置证据

- **适用**：普通交换机端口上的 Windows/Npcap/Wireshark 被动抓包；可迁移的排查方法。
- **本次坑**：猜测镜像、广播风暴、大包或 DHCP，但未取得交换机配置。60 秒样本最大原始帧 1514 字节；平均速率低，1 ms 时间桶仍有最多 103 包，其中广播/组播最多 98 包。
- **做法/验收**：限定时间、接口和必要字段，区分原始长度与 snaplen 截断；同时看平均值与短时突发，并结合板端计数。PC 捕获批处理/重复可能影响时间桶，不能当作板卡线速测量。
- **不能外推**：未见第三方单播不能排除镜像；相似头部不能证明整帧重复；短时没有 DHCP Offer/ACK 不能证明无 DHCP 服务器；一个 ARP 样本不能排除静默 IP 冲突。DHCP 存在本身不是静态地址失效的证据。

## N08：MAC、IP、路由和 USB 身份分别管理

- **适用**：同固件多接口/多板设计；本案只完成算法和登记检查，没有多块实板同时验证。
- **本次实现**：128 位芯片 UUID 经 FNV64 推导本地管理单播地址块，低 4 位为接口角色（USB 板卡端、USB 主机端、ETH0、两个预留口）。同板末字节接近是设计行为；不同 UUID 通常产生不同地址块，但不能保证无碰撞。无效 UUID 拒绝初始化，不退回公共 MAC。
- **风险/验收**：预留角色及地址标志后约 42 位板卡空间，哈希仍可能碰撞。集中台账检查已登记冲突，碰撞时暂停分配；本地串行 JSON 台账不是多工位并发分配服务，无法仅凭相同 UUID 识别物理克隆板。
- **不能外推**：MAC 不同无法解决多板 ETH0 相同静态 IP 或同 PC 上多个 USB 相同子网的路由歧义。生产需逐板 IP/DHCP 策略、USB 子网/路由策略和持久配置；本案 Flash MAC 覆盖尚未实现。

## N09：USB 维护网络的生命周期要隔离

- **适用**：本案 CherryUSB RNDIS 与 ETH 共用 lwIP 的两个独立 netif；不是 USB 网桥。
- **做法/验收**：USB DHCP 服务显式绑定 USB netif，不给 LAN 发租约；维护接口不提供默认网关/DNS，关闭 IP 转发。USB reset/断开作废旧队列与旧会话，避免陈旧完成回调继续消费；不要顺带关闭 ETH 会话。软件重开和实际拔插分别验证。
- **不能外推**：不同 USB 栈的事件、缓冲所有权不同；ESP32/TinyUSB 参考工程不能直接替代 HPM/CherryUSB 实现。SDK 示例 VID/PID 只是本案开发配置，不构成产品标识授权。

## N10：基线、目录和验收结论一起交付

- **适用**：类似单板嵌入式工程，尤其是 RAM 联调和多轮试验；为本案工程组织经验，不强制其他仓库改目录。
- **做法**：一个产品目录包含 `firmware/`、`web/`、`scripts/`、`tools/`、`tests/`、`docs/` 和 `out/`；独立保留原始设计资料与调试器包。临时构建/抓包不散落根目录，已验证历史记录不能当缓存删除。板级覆盖/必要移植留在项目内，保留第三方来源和许可，不直接修改全局 SDK。
- **验收**：精确记录镜像哈希、加载地址/模式、读回、启动版本和测试断言。HTTP 全成功但丢包计数增加仍是回归失败。文档整理只验证文档，不冒称重新执行实板测试。
- **不能外推**：RAM 下载成功不等于 Flash 掉电自启动；网络页能访问不等于参数保存、EtherCAT 或运动功能完成。旧百兆基线不能冒充新版百兆回退测试。
