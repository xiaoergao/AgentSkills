# 锡膏机搅拌放入异常：经验与证据边界

适用：2026-10-22 锡膏机项目的用户现场反馈，以及对同类“放入检测 → 人工处理 → 返回重检”状态图的恢复设计。原项目为 .NET 10 / WPF / WebView2 上位机、轴控实时反馈及 LabVIEW 老流程参考；这些实现细节不是其他机台的前提。

不适用：将本案例的两路输入组合、5 秒时间或状态编号直接套用其他机构；不把本例当作严重故障已通过现场安全验收的证据。

## 现象与证据

- 用户报告：锡膏罐搅拌放入未到位后进入故障，随后条件全部成立而自动复位，存在撞击风险。此处保留为现场报告；本知识整理未独立复现，不能断言唯一根因为某个判断语句。
- 用户要求：感应不到、普通等待信号超时进入警告暂停；继续回到原活动动作/重试。急停、伺服报警、Ready 丢失和异常丢失已回零标志进入严重报警。两种保持都禁止凭条件恢复自动转复位，必须有新的人工操作。
- 此前对话中的局部修复曾涉及将搅拌检测从 500 ms 调为 5 秒，以及允许人工处理后返回检测步骤；后续仍收到本次自动复位报告。因此局部测试通过不能证明“全局锁存、旧请求失效、所有复位入口”均已正确。
- 原项目证据索引：`flow-control/src/FlowControl.Host/Machine/` 中的 `Runtime.cs`、`AutomaticCycle.cs`、`Monitoring.cs`、`SensorConditions.cs`、`TimeoutRecovery.cs` 和 `ManualConfirmation.cs`，以及对应假硬件测试。它们属于原项目，未复制到本公共知识库；文件名只是查找线索，不是冻结版本或本次审查结论。

## 可复用处理

1. 将正常工艺等待异常与严重硬件故障分开；恢复状态保持由执行器负责，图示、界面按钮和执行器使用同一事实来源。
2. 警告保存叶状态及调用栈，人工确认后返回放入检测重新等待真实输入；失败可重复处理，不能跳整机复位或重跑大动作。
3. 报警独立锁存。排查所有发起复位/HOME 的入口，确认它们都要求异常之后的新人工事件，且条件不足时不留下自动待发的复位请求。
4. 暂停若已停轴，继续必须核对原目标并按需重新发令；不能恢复软件流程但让真实轴停在半途。

## 案例参数与迁移要求

本机用户要求的放入检测窗口为 **5 秒**。对话中采用的到位组合为“下对射有效、上对射无效”；这不表示两个感应灯都应亮。复用时必须依据目标机台 IO 命名、极性、安装位置、机构顺序和真实反馈重新核对，不复制点号或默认电平。

新项目应单独确定检测窗口、连续稳定时间、采样新鲜度、停止策略和人员退出条件；机械运动、气源、通信和安全联锁仍按该项目要求检查。普通感应器等待可人工重开窗口；严重故障不能借“调试模式”降级或强制 OK。

本次仅归纳用户要求、场景与验收条件，未操作机台、修改机台程序或执行安全认证。复用后的验收依据是 [恢复协议与验收](recovery-protocol.md) 中的实际状态及命令证据；不继承历史对话的通过数量作为新实现验收。
