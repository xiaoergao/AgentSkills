# 状态保持与恢复协议

适用范围：继承 [Skill](../SKILL.md) 的真实机台顺序控制范围，用于设计和验收警告暂停、报警锁存及人工恢复；下列字段与伪代码为实现建议，不是可直接下载到任意控制器的程序。不适用安全认证实现或未经核对的硬件命令模板。

## 转换约束

| 当前状态 | 事件/条件 | 允许的结果 |
| --- | --- | --- |
| 运行 | 普通工艺等待超时、放入未到位 | 保存上下文，警告暂停 |
| 任意活动状态或警告暂停 | 急停、驱动报警、Ready 丢失等严重故障 | 进入锁存报警，执行项目定义的安全停机 |
| 警告暂停 | 信号恢复，无新人工操作 | 保持警告暂停 |
| 警告暂停 | 新人工继续/重试，实时安全条件及恢复上下文有效 | 返回保存的动作位置，重检或重发必要指令 |
| 警告暂停 | 新人工复位，复位条件满足 | 进入受控复位，不直接续行旧任务 |
| 锁存报警 | 故障消失、急停释放或 Ready 恢复，无新人工操作 | 保持锁存报警 |
| 锁存报警 | 点击继续，严重故障仍在或必须重新回零 | 拒绝直接续行并显示原因，仍保持报警 |
| 锁存报警 | 新人工复位且所有允许复位条件满足 | 进入受控复位；完成反馈通过后才解除相关无效状态 |
| 任意保持状态 | 旧事件、按键持续按住、重连计数变化、刷新 | 不产生恢复动作 |
| 任意保持状态 | 停止/放弃请求 | 保持机械停止，保存已发生事实；不自动复位 |

故障锁存与“原始故障是否仍在”分开保存。多个故障同时存在时不能只检查最后一条。因已回零标志丢失而要求回零时，不可把“该标志已经恢复为真”当作执行 HOME 的前置条件形成死锁；复位前检查通信、急停、驱动 Ready、机构姿态和允许的回零路径，回零后再验证本次回零完成。

普通等料流程本身已定义“无来料则安全退出”的正常业务分支时，应保留其明确业务语义；不要把正常分支误标为严重硬件故障。项目定义为异常等待的超时则按警告保持处理。安全通信看门狗或失去可靠反馈不属于普通工艺等待。

## Deep State / 历史状态需要保存什么

“Deep State”指恢复所需的深层历史上下文；并非仅记一个上层流程名称，也不要求采用某一状态机库。

- 任务/运行身份、配置与动作版本、报警或警告发生序号。
- 活动叶状态、父子调用栈、返回位置、细动作索引。
- 已执行动作及输出结果、待完成指令、原绝对目标、原点查找参数。
- 相对指令的起点及推导出的原终点，防止每次重试叠加原位移。
- 暂停是否发过 STOP、实际轴是否停止、指令是否确认以及可能尚未完成的停止队列。
- 持物/交接、资源归属和已保存业务事实；恢复不能重做已完成交接或重复记账。
- 本次人工请求的身份、发生序号、步骤版本与消费状态。

无法唯一确定上述关键内容时，禁止猜测运动目标或自动重放。对输入等待可由人工重新开始等待窗口；对定位/HOME 的恢复应使用控制器实际协议，不把历史完成位一直为 1 当成本次命令完成。

## 顺序逻辑示意

```text
每次控制循环：
    采集实时反馈
    若发现严重故障：
        锁存所有有效故障；保存活动上下文；按策略停机
        保持 Fault；结束本循环

    若 Fault 已锁存：
        若有本次异常之后的新人工复位请求：
            消费请求；检查允许复位条件与路径
            条件不足：拒绝，保持 Fault（不保留待执行请求）
            条件允许：进入受控复位，不返回旧业务动作
        否则保持 Fault
        结束本循环

    若 Warning 已锁存：
        若有新的人工继续/重试请求：
            消费请求；检查实时安全条件、停止结果和保存的上下文
            通过后恢复原动作位置并重检/重发必要命令
            不通过则保持 Warning，显示原因
        或若有新的人工复位请求：
            消费请求；满足复位条件才进入受控复位
        否则保持 Warning
        结束本循环

    执行一个正常状态步骤；普通异常等待超时则锁存 Warning
```

故障置位的循环必须消费/作废此前未处理的恢复请求，不能先跳到复位再在循环末尾发现严重故障。实际发令也应经同一串行调度或等效原子校验，避免界面读取到“允许”后，故障已变化却仍发送命令。

## 必须验证的行为

每项记录输入变化、状态轨迹和真实/假硬件命令计数，不能只断言页面颜色或文案。

1. 等待到位在窗口结束前不误判；超时进入警告，原任务和调用栈不丢失。
2. 警告期间感应器自行恢复，循环运行任意多次仍保持暂停；没有 HOME 或后续动作。
3. 人工继续后重检真实输入；未到位可再次警告，到位才继续，确认按钮不充当输入值。
4. 警告期间发生急停/Ready 丢失时升级为锁存报警；普通继续入口不能绕过。
5. 严重故障解除、急停释放、驱动重新 Ready 后仍保持报警；没有任何复位或运动指令。
6. 故障仍存在时按复位会被拒绝；随后条件恢复也不会自动执行刚才被拒绝的复位。
7. 复位按钮在故障前已按住、旧点击晚到、连接重建或计数重置均不能触发恢复；必须新按下。
8. 同一按钮事件、重复 HTTP 请求、连续点击不会重复进入复位或重复发令。
9. 轴暂停已发 STOP 时，继续使用原终点重发必要轴动作并等待本次反馈；相对位移不累计，已完成动作不重放。
10. 警告/报警时刷新页面、重连或重启程序不会自动解除保持；缺失上下文时报出具体缺项。
11. 已回零标志丢失与轴离开原点区分；授权 HOME 过程中的正常清位按协议处理。
12. 复位完成后按项目定义回到待机；不能因残留动作请求自动恢复故障前任务。

本清单是复用后的验收要求，不代表已有任意产品通过上述测试。写明假硬件测试、实机验证和长期运行各自覆盖范围。
