# 工业机台：警告暂停、锁存报警与人工恢复

## 适用场景与边界

适用于有真实轴、气缸、传感器和多层动作流程的机台控制；可用于 PLC、LabVIEW 或上位机状态机的设计、修改及代码审查，不限定某种语言、控制卡或软件框架。

| 场景 | 应用方式 |
| --- | --- |
| 搅拌放入检测、夹爪/气缸到位等待超时 | 警告暂停，保留当前动作；人工处理后重检或重试 |
| 暂停后轴已收到 STOP，点继续却不动作 | 保存原目标，按反馈重新发令并等待本次完成证据 |
| 故障条件恢复后自行复位、回零或恢复生产 | 检查锁存、旧复位请求、按键沿及所有复位调用入口 |
| 急停、伺服报警、Ready 或已回零标志丢失 | 锁存报警，阻止业务续行；故障允许复位后由新人工请求进入受控复位 |
| 有父子状态图的暂停恢复 | 恢复保存的活动叶状态及父级调用上下文，避免从大动作起点重放 |

不把普通网页错误、无物理执行的演示流程或所有超时统一套用本分级。安全通信失效、反馈过期等应按实际危害归类，不能因名称含“超时”而降为普通等待警告。本技能约束应用流程恢复，不能替代安全回路、安全 PLC、驱动安全功能或项目风险评估。

## 必须保持的行为

1. **等待异常与硬件故障分级。** 普通工艺等待超过上限进入 `Warning/Pause`；急停、驱动报警、Ready 丢失、异常丢失已回零标志等进入 `Fault/E-Stop`。警告期间仍持续监控严重故障，严重故障优先。
2. **锁存异常。** 保存异常级别、原因、时间与恢复上下文，直到明确的人工恢复操作被接受。原始信号恢复只改变“当前条件／是否允许恢复”，不能自动解除锁存、复位、回零或推进状态。PLC 可用 SET/RST 或等价状态存储；不能用直接跟随输入的 OUT 线圈替代锁存。
3. **必须有新人工事件。** 接受异常发生后的界面点击或物理按钮新按下沿。消费一次事件后失效；禁止复用旧请求、持续高电平、重连前计数、页面刷新或历史会话中的命令。条件不允许时拒绝本次操作，不挂起为“以后条件好了自动执行”。
4. **警告继续与复位是不同操作。** 继续／重试返回保存的 Deep State（活动动作状态及必要的父子调用栈），重新判断真实反馈或重试受影响动作；不能默认跳复位或重跑整个任务。选择复位则须另有明确人工请求，并通过复位路径条件。
5. **报警禁止直接业务续行。** 严重故障解除到允许复位的状态、复位路径满足条件且收到新人工复位请求，才允许进入受控复位。急停释放不代表复位；复位也不等于自动恢复生产任务。
6. **继续不是强制 OK。** 操作员确认仅说明已处理现场，不替代传感器、轴位置、停止反馈、Ready、通信或联锁证据。普通等待可由人工重新打开检测窗口；仍未到位则再次警告，不能直接放行。
7. **续动核对真实执行状态。** 如果暂停发过 STOP，继续不能只恢复一个“运行”标志。需要按保存的原终点重新下发尚未完成的轴命令，重新等待本次完成；已完成动作不重放。相对运动必须避免重复累计位移。
8. **禁止重启绕过保持。** 程序重启、断线重连、换页或重新加载配置不能自动清故障或重放动作。上下文无法确定时保持停止并说明缺失项。

## 实施顺序

- 找齐异常、暂停、停止、复位、HOME、继续的调用入口，包括实体输入监听、界面、后台 Tick、状态图和启动恢复；检查实际执行器而不仅是图示。
- 按项目明确的信号语义分类：轴离开原点后原点灯熄灭是正常现象；“已回零标志丢失”是另一种事件。正在执行 HOME 时标志清零须按该控制器协议判定，不能与异常丢失混淆。
- 为每种可恢复警告明确恢复叶状态、原目标、已发令/已完成记录和人工按钮，建立单一恢复入口；在发运动前再次检查状态和请求有效性。
- 确保状态转换有优先级且一次循环不会连续穿透“警告/报警 → 复位 → 运动”。所有恢复入口共同校验锁存、实时联锁、事件新鲜度和指令状态。
- 界面清楚显示“警告暂停”或“锁存报警”、原因、当前活动步骤与操作是否允许；提供继续/重试、停止、复位中适用的按钮，按钮被拒绝时说明原因。
- 用可控反馈验证信号自动恢复、旧按钮沿、连续点击、重启/重连和停轴后继续。无明确授权，不以实机运动来验证文档或演示。

具体状态转换、恢复数据与验收用例见 [恢复协议与验收](references/recovery-protocol.md)。复用锡膏机经验前，读取 [现场案例及证据边界](references/solder-placement-case.md)；其中 5 秒为该案例要求，不是通用超时值。
